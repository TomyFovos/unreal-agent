# コンテキストとプロジェクト指示書 (Context & Project Instructions)

**言語:** [English](../context.md) | 日本語

Unreal Agent では、ディスク上の正規セッション履歴（Canonical History）がそのまま変更・削除されることはありません。モデルへ送る入力は正規履歴から毎回**派生ビュー（Derived View）**として構築されます。ツール結果の省略（Pruning）や会話の要約（Compaction）はモデルへの入力ビューだけを圧縮し、元の会話・Operation・Receipt はすべてそのまま保持されます。

---

## 1. Codex のコンテキスト管理

Codex（`openai-codex`）では、[コンテキストビルダー](../../harness/contextbuilder/compaction.go)が記録順に入力アイテムを構築します。

- **プレフィックスの安定維持（キャッシュ最適化）:** prune / compact 境界やモデル変更がない限り、前回の入力の末尾に差分だけを追加します。プロンプトの先頭部分を毎回再構築・並べ替えしないため、プロンプトキャッシュが最大限維持されます。
- **モデル変更時の境界記録:** 同じプロバイダ・モデルを使い続ける間は暗号化された推論トークンやアイテム ID を再利用します。プロバイダやモデルを切り替えた場合は境界を記録し、それ以前の履歴を汎用表現に変換します。

### ツール結果の省略 (Tool-Result Omission / Pruning)

大きなツール出力や古くなったファイル読み取り結果は、2段階で圧縮されます。

1. **記録時の先頭・末尾切り詰め:**
   - 非常に長いツール出力は、記録時に `max_output_length`（既定値: 40,000 文字）で先頭・末尾のみに縮約されます（Receipt、Operation、および記録された出力ファイルがあればそのファイルは残ります）。
   - すべてのツールが全文出力ファイルを保存するわけではなく、たとえばネイティブ `read` は `max_bytes` で返却本文を制限し、別の全文ファイルは作りません。
2. **リクエスト時の Pruning ([`tool_pruning.go`](../../harness/contextbuilder/tool_pruning.go)):**
   - モデルへリクエストを送る前に、直近のツール結果をトークン予算内で残し、それより古いツール結果の本文を短い参照情報（Canonical Unit ID と、記録されている場合のシェル出力ファイルパス）に置き換えます。
   - **古い読み取り結果の自動無効化:** 同じファイルに対して後からネイティブの `read` / `write` / `edit`、適用済みの `ast_edit`、または単純な読み取り Bash コマンドが成功・完了した場合、過去の古い読み取り結果は省略候補になります。失敗・未完了の読み取りやプレビューだけの AST 編集は根拠になりません（別の対象が失敗しても、実際に変更された個別対象は根拠になります）。
   - **保護される要素:** 実行中の Operation、未確認の継続処理、ユーザーや親からの入力、アシスタントのテキスト応答、推論トークンは省略されません。

### 自動要約 (Summarization / Compaction)

ツール結果の省略だけではコンテキスト予算に収まらない場合、自動要約が実行されます。

1. **要約のしきい値:** 以下の3つのうち最小の値を超えたときに発動します。
   - コンテキストウィンドウの `80%`
   - `コンテキストウィンドウ - 最大出力トークン - 64,000`
   - 設定された `InputBudget`
2. **要約の仕組み:** まず省略可能な古いツール結果を参照に置き換え、それでも足りない場合は同じプロバイダ・モデル・キャッシュ ID を使って要約を生成します。要約結果と置き換え範囲を記録し、直近の履歴と必要な継続状態を残します。
3. **コンテキスト溢れ時の自動リトライ:** プロバイダからコンテキスト上限超過エラーが返った場合は、強制的に要約を実行して通常リクエストを1回だけリトライします（それでも必須入力が収まらない場合は `required_context_exceeds_budget` を返します）。

> **トークン予算と統計に関する補足:**
> - **トークン数の推定:** 予算判定のトークン数は推定値であり、取得できる場合は直近の実測リクエストに合わせて補正されます。
> - **上限・出力不明時の代替値:** ウィンドウ上限が不明な場合は `FallbackWindow`、最大出力が不明な場合はしきい値計算に `ResponseReserve` を使います。
> - **`/analyze` の prune 統計:** `/analyze` の prune 件数・節約値はリクエスト時の省略を表し、記録時の切り詰めとは別です。

### コンテキスト設定 (`runtime.json` の `Context`)

[`harness/contextengine/types.go`](../../harness/contextengine/types.go) で定義されている設定項目です。

| キー | 既定値 | 意味 |
| --- | --- | --- |
| `FallbackWindow` | `786432` | カタログのウィンドウが不明な場合の代替値 |
| `ResponseReserve` | `4096` | 応答予約量、および最大出力不明時のしきい値計算用の代替値 |
| `ToolResultKeepTokens` | `15000` | 古いツール結果を省略候補にする前に保護する、直近ツール結果のトークン予算 |
| `ToolResultMinPruneTokens` | `15000` | 新しい `prune` 境界を記録するために必要な最小推定節約トークン数 |

Claude 経路の設定は `Claude.CompactThresholdTokens`（既定 `200000`）で、`Context` と Session identity の外に置きます。旧 `Context.ClaudeCompactThresholdTokens` も読み込めます。新しい経路設定が非ゼロなら、そちらを優先します。

## 2. Claude の会話圧縮 (Compaction)

Claude ルートでは Claude Code 自身が会話を管理しているため、Unreal が `claude` CLI を通じて自動圧縮を制御します。

- **アイドル時のバックグラウンド圧縮（既定: 200,000 トークン超）:** 1つのターンとすべてのツール実行が完了した時点で、直近のコンテキスト量が `Claude.CompactThresholdTokens` を超えていれば、バックグラウンドで同じ Claude Code 会話に対して `/compact` を実行します。
  - 圧縮中に新しいユーザー入力やサブエージェントからの通知が届いた場合は、即座にバックグラウンド圧縮を中断して次のターンを開始します（圧縮は次回アイドル時に再試行されます）。
- **ターン開始前のブロッキング圧縮（しきい値の2倍＝400,000 トークン超）:** コンテキスト量がしきい値の2倍を超えた場合のみ、次のターンを開始する前に圧縮完了を待ちます。
- **フッターのコンテキスト表示:** ツールループ全体の合算ではなく、最新の `message_start` の入力トークン数（`input + cache_read + cache_creation`）を表示します。

## 3. プロジェクト指示書 (`AGENTS.md` と `CLAUDE.md`)

プロジェクト指示書はモデルの振る舞いをガイドするものであり、ツール権限や認証情報、セッションの操作権限を付与するものではありません。

### Codex での扱い（セッション作成時のスナップショット）

- **作成時に固定:** セッションを新規作成する際、ワークスペース直下の `AGENTS.md`（[`discover.go`](../../harness/projectinstructions/discover.go)）を読み取り、その正確なテキストをスナップショットとして永続化します。
  - ファイルが存在しなければ「指示なし」を記録し、存在しても読み取り不能・不正な場合は新規 Session の作成に失敗します。
  - 保存済みスナップショットがない旧 Session では、resume 時に `AGENTS.md` を新規探索しません。
- **再開・サブエージェントでも同一内容を維持:** セッションの再開（resume）、再起動、フォーク、および子エージェントの起動時には、保存されたスナップショットがそのまま使われます。ディスク上の `AGENTS.md` を編集した場合は、新しく作成したセッションから反映されます。
- **読み取りと検証の規則:**
  - サブディレクトリ内の指示書探索や `@import` の展開は行いません。NUL バイトや不正な UTF-8 を含むファイルは拒否されます。
  - 探索には `os.ReadFile` を使用します（シンボリックリンクを辿らない保証やファイルサイズ制限はありません）。
  - 保存内容の読み込み時はスキーマを検証し、digest やバイト数の再計算による照合は行いません。

### Claude での扱い（呼び出しごとの読み取り）

- Claude Code は自身で `CLAUDE.md` を読み取ります。
- Unreal は `claude` CLI を呼び出すたびに現在のワークスペースの `AGENTS.md` を読み取り、`CLAUDE.md` 内に `AGENTS.md` という文字列が含まれていない場合に限ってプロンプトへ追加します（[`prompt.go`](../../harness/llm/clients/claudeagent/prompt.go)）。
- `AGENTS.md` の文字列検査は、Claude Code が実際に import した証明ではありません。
- そのため、Claude では既存セッションの途中でも `AGENTS.md` や `CLAUDE.md` の編集が次のターンから反映されます。

## 4. 圧縮とトークン節約状況の確認

TUI で `/analyze` を実行し、**Context** または **Usage** を選ぶ（またはレポートをエクスポートする）と、以下の項目を確認できます。
- 呼び出しあたりの平均入力トークン数（要約リクエストを含む）
- 省略されたツール結果の件数、prune 境界数、推定節約トークン数
- キャッシュヒット率
- Claude の自動圧縮履歴（所要時間、圧縮前の入力サイズ、完了/中断/失敗のステータスと理由）

各数値の詳しい見方は [トラブルシューティング — 診断と計測値の見方](troubleshooting.md#read-analysis-and-measurements) を参照してください。
