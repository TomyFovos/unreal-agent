# Session の復元（A11）

`<session-id>.session.jsonl` が正本です。コンテキスト圧縮後も、応答本文、プロバイダーの生の使用量、Operation の各状態、受領記録を append-only の履歴に保持します。履歴の閲覧、コピー、エクスポートは正本の内容を利用できます。

対話 Session の Host は writer lease の下で、ストアの書き込みヘッドと正本上のレコード位置を `<session-id>.restore-checkpoint` に保存します。チェックポイントは、どの Item まで含むかと、その時点の最新 Operation が正本のどこにあるかを示します。本文や Operation の出力は正本から取得します。更新は正本への同期済みの追記 1,024 レコードごとと、writer lease を返す直前に、一時ファイルの同期と rename で公開します。

Open はチェックポイントの版、Session ID、バイト境界、チェックポイント自体と正本の先頭範囲の SHA-256 を確認します。確認できた範囲の Item を位置から読み出し、Operation はその時点の最新状態を取得します。ストアの状態遷移を適用するのはチェックポイント以降の確定レコードです。チェックポイントがない場合や検証に失敗した場合は正本の先頭から復元します。正本への追記が済んだ時点でプロセスが終了しても、次の Open がその追記を読み込みます。キャッシュの保存失敗は正本への追記結果と独立しています。

Coordinator は復元した Item を順に読み、現在の Registry／Translator と Context Engine でモデル入力を再構築します。要約、ターン途中で受け取った peer の入力、失敗したターン、子の再接続も正本に従います。Permission はワークスペースの `permission-mode` から選択値を読み、子は親のモードに従います。

読み込みでは大きな JSON の包みを途中で複製せず、標準形式のモデル応答を型付きで直接デコードします。Coordinator への読み取りページは本文の文字列を共有し、変更可能な値をコピーします。Host の表示履歴は必要な先頭マーカーだけを調べ、Observe は最近のページと古い表示用メタデータを組み立てます。古い応答の使用量はカウンターと報告の有無を渡します。帰属表の全体は完全な履歴で参照できます。

## 計測

既存調査の M3／M4 合成ログ 50,000 Item・112.86 MB を `b0e768a` と比較しました。元のベンチと同じ、コンテキスト圧縮を有効にしていない Builder を使いました。Go 1.27.1、CPU 0・1、`GOMAXPROCS=2`、通常の OS キャッシュで Open を各 3 回、`Observe(64)` を各 9 回測定し、経過時間と `TotalAlloc` 差分の中央値を示します。Coordinator の復元は Open が返った後にも進みます。モデルは起動していません。

pprof で確認した修正前の主な負荷は、ログの読み込みバッファと JSON の多段コピー、表示マーカー判定時の本文整形、Coordinator のページの反射コピー、Observe の全文分割・書記素走査・JSON 往復です。M3 相当のキャッシュは 1.43 MB でした。

別の合成ログ（5,250 Item、145.63 MB、使用量の帰属表と 125 Operation の反復更新を含む）では、`host.read_restore` は修正前 2,641.8 ms／1,352.97 MB、修正後の全リプレイ 1,150.5 ms／451.40 MB、チェックポイント使用時 685.6 ms／386.96 MB でした。このキャッシュは 0.16 MB です。

## 回帰テスト

生成したログでチェックポイントと全リプレイの書き込みヘッド、最新 Operation、Item を比較します。旧版、破損、部分書き込み、正本の範囲不一致、正本への追記直後の中断、キャッシュ書き込み失敗も検証します。Host の統合テストでは、圧縮、途中の peer 配信、子が稼働中の親の失敗ターンを復元し、Responses クライアントが生成するリクエスト本文とワークスペースの Permission 選択を照合します。
